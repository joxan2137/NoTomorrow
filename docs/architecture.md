# No Tomorrow — iOS architecture and implementation contract

Read this before touching any feature. The prototypes in `design/*.dc.html` are the visual spec; this file is the code spec.

## Stack

- SwiftUI, iOS 17+, Swift 5 language mode, `@Observable` for view state, SwiftData for persistence.
- Project is generated by XcodeGen from `project.yml`. Files are picked up by folder: anything under `NoTomorrow/` joins the app target, `NoTomorrowWidgets/` the Live Activity extension, `Shared/` both. Never edit `NoTomorrow.xcodeproj` by hand; run `xcodegen generate` after adding folders (adding files to existing folders needs no regeneration).
- Type-check fast with `scripts/typecheck.sh` (whole app module, ~7 s, safe to run in parallel). Full build: `xcodebuild -project NoTomorrow.xcodeproj -scheme NoTomorrow -destination 'id=<sim udid>' -derivedDataPath build/DerivedData build`.
- Dark-only. Never use `.primary`/`.secondary` system colors or `Color(.systemBackground)`; use `NT.Colors.*`.

## Folders

```
NoTomorrow/App            NoTomorrowApp (container, environment objects), RootView (onboarding vs tabs), AppState
NoTomorrow/DesignSystem   Theme.swift (NT.Colors/Fonts/Spacing/Radius/Size), Components.swift (buttons, cards, chips, rings, rows)
NoTomorrow/Models         Models.swift — every @Model + enums; NoTomorrowSchema.models
NoTomorrow/Services       RestTimerController, WorkoutSessionController, ExerciseLibrary, Formatters (Fmt), + per-feature services
NoTomorrow/Features/<X>   one folder per tab/flow; each owns its views + view models
NoTomorrow/Resources      Localizable.xcstrings (en + pl), exercises.json, Fonts, Assets
Shared                    RestTimerAttributes (ActivityKit payload)
NoTomorrowWidgets         Live Activity UI
```

`Features/Placeholders.swift` holds stand-in views (`DashboardView`, `TrainView`, `FuelHomeView`, `ProgressHomeView`, `BroView`, `OnboardingFlow`). When you implement one, DELETE its stand-in from that file and create the real type with the SAME NAME in your feature folder. Do not rename these entry types; `RootView` references them.

## Environment objects available in every view

```swift
@Environment(AppState.self) var appState                 // selectedTab, hasOnboarded, pendingRoute
@Environment(RestTimerController.self) var restTimer     // start(seconds:exerciseName:nextSetLabel:workoutName:), adjust(by:), skip(), remaining, progress, isRunning
@Environment(WorkoutSessionController.self) var session  // activeWorkout(in:), begin(_:), end(), showsActiveWorkout
@Environment(\.modelContext) var modelContext
```

Query SwiftData with `@Query` in views or `FetchDescriptor` in view models. `UserProfile` and `GymSchedule` are singletons: fetch the first, create if missing (onboarding creates them).

## Design rules (from the canvas)

- Screen background `NT.Colors.ground`; 20 pt horizontal padding (`NT.Spacing.screenH`); sections separated by whitespace or `Hairline()`, not by cards. One `NTCard` per screen for the object that matters (next session, portion sheet, code).
- Type: `NT.Fonts.largeTitle` for tab titles with an `eyebrow()` line above (date, context); `headline` for section titles; `subheadline`/`footnote` in `ink2` for secondary; `NT.Fonts.display(n)` ONLY for hero numbers (time, kcal left, e1RM, volume) and the wordmark. Numbers in columns or that tick get `.tabular()`.
- Buttons: `PrimaryButton` (white) is the one thing to do; `SecondaryButton` (surface-2) beside it, equal widths in a card row (52 pt), 56 pt for full-width bottom CTAs; `GhostButton` for tertiary. Never an icon inside a card-row button.
- Ember (`NT.Colors.ember`) only for: next-session eyebrow, gym-day dots/attended checks, progress lines and rings, PR badges/trophies, streak icon. Green = confirmed, rose = missed/destructive. Everything else white/grey.
- Hit targets ≥ 44 pt (wrap small visuals in a 44 pt frame with `.contentShape`). No fake status bar. Respect safe areas; content scrolls under the tab bar.
- Every string through the catalog: `Text("key")` with keys from `Localizable.xcstrings`; add new keys with BOTH `en` and `pl` values (Polish: sentence case, "ty" form, no gendered past tense, decimal comma comes free from formatters). Use `Fmt` for numbers/dates.
- Empty states are designed, not blank: one line of copy + the action.

## Feature contracts

### Onboarding (`Features/Onboarding`) — `OnboardingFlow`
Three steps with a 3-segment progress bar and back arrow: You (name, body weight + kg/lb, goal chips, suggested daily target card computed by `TargetCalculator`), Schedule (7 day toggles Mon-first, wheel time picker, two reminder toggles), Pair (code card with share, "or enter your bro's code", Continue, "Not now"). Welcome screen before step 1: wordmark, tagline, language segmented control (English / Polski → `appState.languageOverride` "en"/"pl"), Get started. On finish: insert `UserProfile` + `GymSchedule`, set `appState.hasOnboarded = true`.
`TargetCalculator`: Mifflin–St Jeor with assumed 30 y / 178 cm when unknown, activity 1.55, +300 kcal build / −400 lose / 0 maintain; protein 2.2 g/kg build, 2.4 lose, 1.8 maintain; fat 0.9 g/kg; carbs = rest. Round kcal to 50.

### Dashboard (`Features/Dashboard`) — `DashboardView`
Eyebrow date + "Today" large title + avatar (opens `SettingsView` sheet). Week strip (Mon–Sun of current ISO week): letter labels from `weekday.*` keys; gym days get an ember dot; attended = ember ring + check; missed = rose ring + x; today = white filled circle. Next-session card: eyebrow "dashboard.nextSession" + routine name; hero time `display(64)`; relative day + countdown (`Fmt.relativeDay`, `Fmt.countdown`); bro row (state machine: no bro → "dashboard.noBro"; bro in, me not → "dashboard.broIsIn %@" with green dot and time; both in → "dashboard.bothIn" with both times); button row: not confirmed → `I'm in` + `Can't make it`; confirmed → `Start workout` (or `Back to workout` if a session is active) + `Can't make it`. Rest day → the card shows the next gym day instead. Fuel summary row (ring 64 pt with kcal left + "left", three `MacroBar`s) navigates to Fuel tab. Last session row: name · duration · "n PRs" ember, PR chips. `Can't make it` opens `CantMakeItSheet` (Bro feature).
Attendance: confirming writes/updates `AttendanceRecord(day: today, participant: .me, status: .confirmed)`; finishing a workout on a gym day marks `.attended`; the 21:00 check and misses are handled by `AttendanceService` (Services) which also derives the strip states.

### Train (`Features/Workout`) — `TrainView`, `ActiveWorkoutView`, `ExercisePickerView`, `RestTimerView`, `WorkoutDoneView`
`TrainView`: if a workout is active → banner "Back to workout"; routines list (seeded Push A / Pull A / Legs on first run by `RoutineSeeder` using exercise ids from exercises.json: "Barbell_Bench_Press_-_Medium_Grip", "Barbell_Shoulder_Press", "Incline_Dumbbell_Press", "Triceps_Pushdown", "Side_Lateral_Raise"; "Barbell_Deadlift", "Bent_Over_Barbell_Row", "Pullups", "Barbell_Curl", "Seated_Cable_Rows"; "Barbell_Squat", "Romanian_Deadlift", "Leg_Press", "Leg_Extensions", "Standing_Calf_Raises" — look up by id, skip missing) with "Start workout"; "Start empty workout"; history list (most recent first, name · date · duration · volume · PRs).
`ActiveWorkoutView` (full-screen cover, `session.showsActiveWorkout`): header routine name + elapsed timer (ember dot) + "Exercise i of n"; `Finish` (surface-2, 44 pt) → confirmation; per exercise: name, "Last: 80 × 8" from the most recent completed set of that exercise in a previous workout; column header Set · Previous · kg · Reps · ✓ (`.cap` ink2); set rows 44 pt: set number (tap → menu W/D/F/normal), previous ghost value, two 60×44 numeric cells (`TextField` with `.keyboardType(.decimalPad)`, prefilled from previous), 28 pt check in a 48 pt column. Ticking a set: sets `completedAt`, computes PR/set record via `RecordService`, shows the ember hint "workout.beatsBest", starts the rest timer with the exercise's `restSeconds` (skip auto-start if the NEXT set is a drop set). Add set duplicates the last row. Add exercise → `ExercisePickerView` sheet (multi-select). Rest timer pill floats above the bottom when `restTimer.isRunning` (ring, mm:ss, +15, Skip); tap → `RestTimerView` sheet with the 280 pt ring, `display(104)` time, −15 / Skip rest / +15, "Up next" card (next set target = last completed set of this exercise), lock-screen note. Finish → mark `endedAt`, attendance `.attended` if today is a gym day, present `WorkoutDoneView`: "DONE." display, volume `display(56)` + "kg moved", delta vs the last workout with the same name, tiles Time/Sets/Exercises, "Records tonight" list (PRs ember trophy, set records grey medal) or the no-records line, Done.
`ExercisePickerView`: search field, muscle chips (`ExerciseLibrary.MuscleGroup`), rows name + muscles + last set or "Never done", multi-select rings, exercises already in the workout show "In"; "Create "<query>" as a new exercise" row inserts a custom `Exercise` (id "custom-<uuid>", primaryMuscles from selected chip); bottom `Add n`.
`RecordService` (Services): given a completed set, look at every earlier completed set of that exercise; PR = new max Epley e1RM or new max weight; set record = most reps at that weight. Marks `isPR` / `isSetRecord`.

### Progress (`Features/Progress`) — `ProgressHomeView`, `ExerciseProgressView`
Home: eyebrow last PR date, "Progress" title, segmented Lifts / Body. Body card: latest weight `display(40)`, 4-week trend delta, sparkline of raw (grey) + smoothed 7-day moving average (ember) using Swift Charts, "Log weight" sheet inserting `BodyWeightEntry`. Lifts list: every exercise with ≥1 completed set, sorted by last PR date desc: name, routine context/last PR, 72×24 sparkline of e1RM over time (ember if PR in last 30 days else grey), current e1RM + delta over the range. Tap → `ExerciseProgressView`: back + name + segmented 1M/3M/1Y/All; hero e1RM `display(64)` + delta chip; Swift Charts line+area of best e1RM per session with PR markers; tiles Last PR / This week volume / Sessions; weekly volume bar chart (all lifts, last 8 weeks, current bar ember); Records list (heaviest set, most reps) with dates. Empty state "progress.empty".

### Fuel (`Features/Fuel`) — `FuelHomeView`, `FoodSearchView`, `PortionSheet`, `BarcodeScannerView`, `AIScanView`
Home: eyebrow date + "Fuel" title + protein streak chip (target icon); hero ring 132 pt with kcal left `display(44)` + "fuel.kcalLeft", three `MacroBar`s (protein bar white, others ink2), "eaten · goal" line; meals list Breakfast/Lunch/Snack/Dinner (entries as name · grams; kcal right; AI entries get an "est." `Badge`); the empty slot shows "fuel.nothingYet" + ember hint "protein to go"; bottom bar three 56 pt tiles: AI photo (white), Barcode, Search. Day navigation: swipe or chevrons in the eyebrow (yesterday/today).
`FoodSearchService` (Services): Open Food Facts. Search: `GET https://world.openfoodfacts.org/cgi/search.pl?search_terms=<q>&search_simple=1&action=process&json=1&page_size=24&fields=code,product_name,product_name_pl,brands,quantity,serving_size,serving_quantity,nutriments,image_front_small_url,countries_tags&lc=<pl|en>`; barcode: `GET https://world.openfoodfacts.org/api/v2/product/<code>.json?fields=...&lc=pl`. Header `User-Agent: NoTomorrow/0.1 (markzaluben@proton.me)`. Debounce 500 ms, minimum 2 characters, never search-as-you-type faster than that (rate limit 10/min). Map to `FoodItem` (id "off:<code>", kcal from `energy-kcal_100g`). Cache results in SwiftData on tap. Barcodes from VisionKit arrive as EAN-13; if 13 digits starting with 0, also try the 12-digit UPC-A form.
`FoodSearchView` (sheet, "Add to <meal>"): search field + barcode button, Recent (last 10 `FoodItem` by `lastUsedAt`), results rows (name, brand · per 100 g · P x g, kcal, + button 32 pt in a 44 pt hit box). Tap row → `PortionSheet` over a scrim: name/brand/source, kcal `display(40)` for the amount, −/+ stepper (10 g), quick portions (100 g, serving if known), macros row, `Add to <meal>` 56 pt. Not found → "fuel.notFound" + Quick add (name, kcal, P/C/F).
`BarcodeScannerView`: `DataScannerViewController` (VisionKit) wrapped in `UIViewControllerRepresentable`, symbologies ean13/ean8/upce, rear camera, single item; on simulator/unsupported show a manual code field instead.
`AIScanView`: PhotosPicker + camera (UIImagePickerController); downscale to 1024 px long edge JPEG 0.8; call `AIEstimateService.estimate(imageData:mealHint:locale:)` → `AIEstimate { foods: [AIFood(name, grams, kcal, protein, carbs, fat, confidence 0…1, isGuess)], overallConfidence }`. Result screen per canvas: photo with detection tags, Estimated total `display(56)` + macros + confidence dots, editable rows (grams stepper recomputes kcal proportionally), "guess" badge for low-confidence items, "Add something it missed" (opens FoodSearch into the same plate), disclaimer "fuel.ai.disclaimer" in ink2 with info icon, buttons Save as recipe (secondary) / Log to <meal ▾> (menu). Logging inserts one `MealEntry` per food with `isAIEstimate = true`.
`AIEstimateService` is a protocol; ship `MockAIEstimateService` (returns a plausible 3-item plate after 1.2 s) and `BackendAIEstimateService` that POSTs multipart `image` + `meal` + `locale` to `BackendClient.baseURL/ai/estimate` and decodes the same JSON. Pick via `AppConfig.aiProvider` (`.gemini` default via backend, `.claudeBYOK` when the user stored a key in Keychain → send header `X-Anthropic-Key`).

### Bro (`Features/Bro`) — `BroView`, `CantMakeItSheet`
Paired state: eyebrow "Kuba & Tomek", "Bro" title, streak chip "n of m together" (flame). Shared-week card: header letters, two rows (You / partner) of 30 pt status cells (attended ember check, missed rose x, planned ring, today = white "In" when confirmed), hairline, today line "Today · 18:00 · Push A" with "You 09:12 · Tomek 12:40" and "Both in" green dot. Heads-up chips row bleeding to the screen edge: Can't make it (rose outline), 15 min late, Let's go, Custom (≤ 80 chars). Log: header "Since <date> · n sessions · m missed", rows date · routine · outcome (+ note) with two status cells. Unpaired state: title "bro.unpaired.title", subtitle, big code card (share + copy), enter-code field + Pair. All data through `BroService` (Services) which talks to `BackendClient` (protocol) — ship `MockBackendClient` with an in-memory partner "Tomek" who confirms 20 s after you do, so the flow is demoable offline. `CantMakeItSheet` (also opened from Dashboard): title, session line, Why chips (sick/work/tired/family/no excuse), note field with 80-char counter, "Propose a make-up" day chips (next 2 non-gym days + Skip this one), summary box (rose calendar icon), `Send to <partner>` (or `Log as missed` when solo), "Never mind, I'm going". Sending writes `AttendanceRecord(.cancelled, reason, note, makeUpDay)` + `HeadsUp(.cantMakeIt)` and calls `BroService.send`.

### Settings (`Features/Settings`) — `SettingsView` (sheet from the avatar)
Grouped `NTCard`-style groups with `ValueRow`s per the canvas: You (Name, Body weight, Daily target), Training (Gym days · time, Rest timer · auto-start, Units), App (Language: System/English/Polski → `appState.languageOverride` and relaunch hint, Notifications, Health app, Export my data → CSV via ShareLink, AI estimates: Gemini (default) / Claude with your key → Keychain), Gym bro (partner row, Your code with share), Account (Sign out, Delete account and data in rose). Each row pushes a small editor. `HealthKitService` (Services): request bodyMass read/write, dietaryEnergyConsumed/protein/carbs/fat write, workouts write; wrap in `#if canImport(HealthKit)` and check `HKHealthStore.isHealthDataAvailable()`; degrade gracefully on simulator.

## Backend contract (Fly.io, later) — `Services/BackendClient.swift`

```swift
protocol BackendClient {
  var baseURL: URL { get }
  func signIn(apple identityToken: String, authorizationCode: String) async throws -> Session
  func signIn(google idToken: String) async throws -> Session
  func signIn(username: String, password: String) async throws -> Session
  func register(username: String, password: String, email: String?) async throws -> Session
  func me() async throws -> Me
  func createPairCode() async throws -> String
  func pair(withCode: String) async throws -> Partner
  func unpair() async throws
  func pushSchedule(_ s: ScheduleDTO) async throws
  func partnerState() async throws -> PartnerState           // schedule, attendance for the week, unread heads-ups
  func setAttendance(day: Date, status: AttendanceStatus, reason: String?, note: String?, makeUpDay: Date?) async throws
  func sendHeadsUp(kind: HeadsUpKind, text: String, sessionDay: Date) async throws
  func registerPushToken(_ token: Data) async throws
  func estimate(imageJPEG: Data, meal: MealSlot, locale: String, anthropicKey: String?) async throws -> AIEstimate
  func deleteAccount() async throws
}
```
`Session { accessToken, refreshToken, userId }` stored in Keychain by `AuthStore`. `MockBackendClient` implements everything in memory.

## Things that are NOT negotiable

- Rest timer state = `RestTimerController` only. Never run your own `Timer` for it; render remaining time with `TimelineView(.periodic(from: .now, by: 1))`.
- No health data leaves the device except the AI photo (explicit user action) and bro attendance/schedule.
- Every user-visible string localized in both languages. Every number through `Fmt`.
- Keep files under ~400 lines; split views into subviews in the same folder.
